# 执行模式与成本边界

## CherryStudio 生产模式：Free Assisted Browser（默认）

CherryStudio 对“实际使用/撤三 + 指定商品”固定使用 `free_assisted_browser`：员工只在专用 Edge（本机无 Edge 时回退 Chrome）完成登录、验证码并保持窗口打开，随后脚本通过 loopback CDP 附着同一实例，按 `scripts/runtime-policy.json` 配置的销售平台和公开搜索提供方执行动态矩阵、少量详情粗检、企查查图样比对和线索 PDF 汇编。任何验证/阻断状态立即熔断对应平台或提供方，不进入交付材料。该入口必须以终态审计收据为完成条件。

## Quick（仅 CLI/Codex 显式模式）

Quick 用于 CLI/Codex 显式初筛，目标是在不牺牲正式入卷页面真实性的前提下减少搜索、抓取和模型调用；当前 CherryStudio 单一生产入口不接受 Quick。

| 项目 | 默认门槛/硬上限 |
|---|---:|
| 正常搜索提供方 | 至少 1 |
| 合并查询 | 最多 7，满足候选门槛即提前停止 |
| 每查询保留 URL | 最多 6 |
| URL frontier | 至少 8 |
| 目标站点 | 至少 2 |
| 候选榜站点 | 最多 3 |
| 本地候选榜 | 最多 8，每站最多 3 |
| 廉价探测 | 6–8 |
| 完整抓取尝试 | 最少 4、最多 6 |
| 正常直达页 | 至少 4，目标 5 |
| 正式来源 | 4–5 |
| 视觉候选 | 最多 2 |
| 视觉调用 | 最多 2 |
| 可见浏览器/人工点击 | 自动分支禁止；显式真人固证分支允许 |

Quick 中单个查询失败不阻止完成，但必须保留 provider 状态，并在 coverage、results 和 report 中列出失败的 QUERY_ID。全局 URL、站点、抓取和正常页面门槛仍须满足。

Quick 的销售平台请求使用独立的 API-first 分支：按“商标名 + 每一项核定商品”调用已获权的官方 API，先对 API 图片做本地筛选，只归档最多 12 个视觉或文字短名单直达页。API 目录未返回不计为全站零命中。没有 API 凭据或官方响应时报告 `api_not_configured`，不得在 Quick 内自动改成逐个平台首页搜索。用户选择 CherryStudio 默认免费人工登录方案时应进入上面的 `free_assisted_browser`，不是 Quick 的静默降级。

平台自动搜索已被验证码或风控证明不可用，且用户选择人工方案时，改用 `manual-assisted`：真人默认在专用 Edge 中完成导航、查询和验证，仅在本机没有 Edge 时回退 Chrome；Skill 自带本地扩展只在人工点击后归档当前页。该分支不适用上表的自动浏览器禁令，但不得让扩展或脚本操作登录、验证码、搜索框和页面按钮；任务完整性由 `manual-capture-validation.json` 独立校验。

查询按计划顺序执行；frontier 已达到 8 个直达 URL、2 个站点，并能本地排出至少 6 个候选后即可停止后续查询。候选优先集中在 2–3 个信息较强的站点，而不是为增加域名数量扩散到大量低价值网站。

先用 `quick-probe.py` 探测 6 个候选；有效页不足目标 5 个时，最多补探到 8 个。验证码、登录、拒绝、超时和内容不符均直接跳过、不重试，只保留 URL 与状态。再用 `quick-capture.py` 对有效短名单做完整归档，目标 5 页、最多尝试 6 个 URL。

抓取完成后用 `build-review-packet.py` 从已接受候选中提取命中词附近的有限正文。Agent 只读取该紧凑 JSON 和必要元数据，不加载整份 HTML/MHTML/正文。未归档 URL 统一写入 `skipped-links.json`，不把失败页面或验证码截图塞进 PDF。

Quick 的查询计划动态合并本次全部商品，避免每个商品和每个平台各跑一轮。`build-query-plan.py` 最多生成：

1. 注册号加商标；
2. 权利人加商标；
3. 商标加前半组商品；
4. 商标加后半组商品；
5. 商标加价格/购买/店铺/包装；
6. 京东限定查询；
7. 淘宝限定查询。

如果缺少注册号、权利人或商品，脚本自动跳过空查询并去重。

候选排序只使用已落盘的搜索结果和 frontier，不联网。候选至少命中商标、注册号或完整权利人之一；商品词、商业词、provider 数量、搜索排名和跨站点多样性只负责加权，不能单独让页面进入榜单。

## Forensic（显式）

Forensic 用于用户明确要求完整调查或法证级卷宗。

| 项目 | 默认门槛/硬上限 |
|---|---:|
| 正常搜索提供方 | 至少 2 |
| 查询 | 最多 36 |
| 每查询保留 URL | 最多 20 |
| URL frontier | 至少 10 |
| 目标站点 | 至少 3 |
| 完整抓取尝试 | 至少 8、最多 30 |
| 正常直达页 | 至少 5 |
| 正式来源 | 最多 20 |
| 视觉候选 | 最多 10 |

Forensic 要求每个 QUERY_ID 至少有一个 normal 或 zero_results 提供方。验证码、no_extractable_results、错误和拒绝不算成功。

## Provider 顺序

Quick：

1. CherryStudio 已实际取得结构化联网搜索 JSON 时，原样保存并导入；
2. 否则先用 360 搜索；失败或明确零结果且覆盖不足时，最多回退一次到百度；
3. 百度结果先解析 `baidu.com/link` 为最终站外 URL，无法解析的跳转不进入 frontier；
4. 不因 provider 失败而切换多个可见浏览器；
5. 不等待人工处理验证码。

Forensic：

1. 使用两个不同受信 base provider；
2. provider 阻断时可切换其他 headless provider；
3. 只有用户明确授权交互登录时才启用 headed；
4. 不把 provider instance 重复计算成多个提供方。

## 入卷质量不随模式降低

Quick 与 Forensic 的差异是覆盖量，不是单页证据质量。所有正式来源仍必须：

- 是真实直达 URL；
- 通过内容断言；
- 保存 MHTML、SingleFile HTML、截图和 PDF；
- 通过禁网回放、正文/图片保留和截图相似度检查；
- 通过哈希与 PDF 空白/重复页验证；
- 排除搜索页、验证码、登录页、拒绝页和空壳页。
